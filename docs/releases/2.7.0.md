# What's new in 2.7.0

Switch to Basic view to focus on a conversation, open a file your agent made beside its reply, or edit Markdown directly in the preview. Settings now puts each AI harness in one place, from sign-in and model choice to CLI launch options.

## Conversations and files

- **Choose Basic or Advanced.** Basic view groups conversations by project and keeps the conversation and its preview together. Switch back to Advanced to use the full set of tools.
- **Open files from a reply.** A file saved to thread storage can open beside the conversation from a link in the reply. To find it again, open a new side-panel tab and search under **Thread storage**.
- **Edit Markdown where you read it.** Search the rendered document, check off a task, or edit across paragraphs in one continuous editor. If another editor changes the file before you save, you can review and reconcile the edits.
- **Ask about a passage.** Select text in a conversation and choose **Ask Zana** to use that selection in a question.

## Experimental Bots

- Turn on **Bots** in **Settings → Experimental**. In Basic view, pin a bot in the sidebar and click it to open its conversation. Click its name above the chat to edit its Markdown personality or manage its routines.
- Use `zcc bots update` to edit a bot from the terminal. Use `zcc bots routine` to schedule work in its main thread.
- The desktop Vault stores replace-only passwords and Salesforce client secrets with device protection. Connect a Salesforce account to let a bot and its routines read the open cases assigned to that account.

## Composer and AI harnesses

- **Set up new chats in Settings → Composer.** Choose the default thread harness, its model and supported thinking effort. Threads and CLI agents have independent defaults. In the desktop thread composer, the model comes first, with mode, effort, permissions and Enter behavior together beside Send.
- **Configure a harness in one place.** Open **Settings → AI Harness**, search for a harness and choose **Configure**. Check credentials, choose a model or search the catalog. The CLI agent switch and launch options are at the bottom of the same entry.
- **Manage provider access per machine.** Supported providers can start their own sign-in flow from Settings. You can also save API keys in the machine's encrypted store. Install **Provider Usage** from Plugins to see the subscription windows reported by Claude Code, Codex and Cursor across your machines.

## Squad plans and runs

- **Fix a plan before launch.** Review plan flags steps that require a role the Squad cannot supply. It suggests corrections and lets you send a fix request back to the conversation that prepared the plan. It also accepts common variations in spacing and capitalization.
- **Keep work with the right role.** New runs enforce every required role on a step. If no worker can take it during a run, the coordinator or a person can resolve the blocker. Runs already in progress keep their original routing.
- **See why a worker stopped.** Squad runs report worker launch failures, recover interrupted work more reliably and honor Stop while workers are starting.

## Navigation and everyday fixes

- **Make room in the sidebar.** Choose the icon-only rail in **Customize navigation**. Hover over an icon to see its keyboard shortcut. CLI agents can open in the top tab bar, and Design Docs can pin individual documents there.
- **Find your place again.** Search within an open Design Doc or the Keyboard Shortcuts panel. Design Docs also restores your place when you switch thread-panel tabs. The command palette's file search now works in large projects.
- **Resume where you left off.** The desktop restores window state after an update and remembers which projects and machines were expanded. On Windows, stopping a CLI agent also stops its child processes.
