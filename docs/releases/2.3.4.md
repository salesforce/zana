# What's new in 2.3.4

**Find settings faster, work with agents beside your plugins, and keep conversations moving.** Zana 2.3.4 adds Design Docs and plugin panel agents, makes busy projects more responsive, and improves agent approvals, recovery and quit protection.

## New

- **Design Docs.** Install the optional plugin from Plugins to write and review specs, RFCs and ADRs with multi-file documents, mermaid diagrams, HTML mockups, review comments and revision history. Agents can read, edit and comment through dedicated tools, and documents can be published as rendered pages with a shared site kit.
- **Search every setting.** Search names, help text, options and current values, with typo-tolerant results in Settings and the command palette. Selecting a result opens and highlights the exact control, including plugin settings and machine cards. Secret values are excluded.
- **Agents beside plugin pages.** Open a new agent from a plugin page’s side panel and keep its conversation beside your work. PR Monitor’s panel agent can manage tracked PRs, filter the board and open PR details.
- **Agents-only sidebar view.** Show just your running agents in the sidebar, each tagged with its project, without the project rows.
- **Send now for queued prompts.** Send a queued prompt immediately from the desktop or an authenticated phone, after a single confirmation.
- **Swipe to close on the phone.** Swipe left on an agent card in the phone kanban to close it.
- **Optional Salesforce toolkit providers.** Use project- and org-scoped Salesforce tools with approval for actions that make changes, plus an improved Agent Script editor toolbar. The toolkit update adds SOQL schema checks, Data 360 write confirmation, Omni-Channel Flow authoring and AgentScript voice review.
- **Prompt Library.** Install the optional plugin from Plugins to browse prompt history, star useful prompts, and restore their structured content into the composer.
- **Native agent questions.** Supported providers can present choices and accept free-text answers directly in a conversation. Answer drafts survive navigation and reloads.
- **Experimental provider controls.** Enable safe-mode and service-tier controls in Experimental settings for providers that support them.

## Improved

- **Design Docs workbench.** Download a complete document as a ZIP, collapse the document list and file tree with remembered state, and filter by status or project with document counts. Open a linked agent conversation beside the document.
- **Easier-to-scan Agents List.** Group agents by project or recent activity, filter unread conversations, collapse status groups and read longer titles. Selected threads retain their right-hand panel.
- **Cleaner conversation panels.** A simpler thread header, clearer question cards, elapsed working indicators and compact background activity make conversations easier to follow. Plugin pages use the available width when their side panel is open.
- **HTML previews.** HTML files open in a rendered side-panel preview with a Code / Preview toggle.
- **Library naming.** The notes and findings plugin is now consistently called Library, keeping it distinct from Design Docs.
- **Smaller archived history.** Archived threads preserve the conversation while compacting tool output, reasoning and other execution details in the background.
- **A more responsive desktop.** Project rosters and unread counts use less repeated work, conversation outlines reuse unchanged history, and hidden panes suspend unnecessary refreshes. Large-repository status checks run in the background, keeping project requests responsive.
- **Lighter Settings startup.** Settings sections load when needed, reducing the initial renderer bundle.
- **Clearer AI Harness settings.** Installation status, searchable model lists, and grouped launch settings make setup easier to inspect and use with the keyboard.
- **Model-list recovery.** Refresh and retry actions recover provider catalogs while retaining usable choices during temporary failures.
- **Models on any machine.** Remote hosts load their model lists without needing a project checkout, and CLI Agents always use the selected host's catalog.
- **Faster startup with plugins.** The desktop becomes ready without waiting for plugins to scan, build or start, and a stalled plugin recovers automatically with bounded retries.
- **Clearer Git import errors.** Importing a project from Git explains access failures, keeps Git's diagnostics, and lets you retry.
- **Project pane dragging.** Dragging from the project sidebar now supports diagonal movement into pane drop targets.

## Fixed

- Quit confirmation now protects running Modern agents and pending questions as well as terminals, including hidden agents. Cancel keeps their work running.
- Worktree agents start in their provisioned worktree rather than the source checkout, and threads use the clearer “Worktree” label.
- Windows provider startup and CLI installation handle command wrappers and executable resolution correctly.
- Pi extension prompts respect timeouts, support number-key selection, and handle oversized content. Follow-up work from extensions stays in the same turn, and unreadable images produce an explanation.
- Slow conversation reads retry once before showing a timeout banner.
- Provider approval and permission changes apply consistently to new and resumed turns, including Plan transitions.
- Queued prompts, attachments, and answer drafts retain their content across navigation and recovery.
- Uploaded images and files are copied to the selected remote host before dispatch, so remote agents receive readable paths.
- Voice retry preserves the recording and original submission without duplicating transcript text.
- Conversation message links, search results, browser download authorization, and browser recovery behave more consistently.
- Provider shutdown and oversized output recovery clean up owned resources without losing later valid messages.
- ACP agents keep their default model when launched as CLI Agents.
- Timed-out Job Team blockers escalate to the coordinator, survive restarts, and can be recovered safely when all work is read-only.
- Modern owner threads wait for their provider to register before starting, avoiding a startup race.
