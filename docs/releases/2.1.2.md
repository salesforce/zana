# What's new in 2.1.2

A Command Center patch that makes the packaged app load its plugins, keeps unattended jobs from stalling on permission prompts, and settles Team runs when a unit fails.

## ✨ New

- **Readable plugin health.** The Plugins hub shows a short reason when a packaged plugin fails to load, with the technical detail available if you need it.
- **Project color dots.** Project rows in the list and session rail keep a stable color so you can scan which project a session belongs to.

## 💬 Improved

- **Packaged plugins stay in the app.** First-party plugin `src/` is no longer stripped from the `.dmg`, and `jiti` stays external so TypeScript plugins load the same way they do in `pnpm start` as they do after a release install.
- **Unattended launches stay unattended.** Scheduled and headless jobs force autonomous routing and refuse interactive permission modes, so they cannot inherit Accept Edits or Plan from global settings and then hang.
- **Composer launch surfaces heal once.** An older CLI-only leftover no longer hides Modern and Team; Settings can still turn individual surfaces off after that reset.
- **Job Team coordinator is event-driven.** After the initial dispatch it parks instead of chatting with workers, and wakes only for blockers, conflicts, and policy escalations.
- **Agents board peeks a live scheduled job.** Clicking a running schedule on the board opens the inspector modal; Scheduler overview still goes to the live page.
- **ACP replies drop echoed instructions.** Harnesses that stream back the injected `<system_instructions>` block (notably Mastra Code) no longer show that echo as the first assistant message.

## 🐛 Fixed

- **Failed Team DAGs settle.** Independent branches keep running; failed descendants skip; the run no longer sits open after a unit fails.
- **OpenCode stale model pins heal at startup.** A leftover `aisuite/*` or dead `llmgw/*` pin in `~/.zcc/config.json` is rewritten so OpenCode no longer exits 64 on launch.
- **`pnpm start` opens the real packaged app.** After `pnpm dist`, `pnpm start` launches `Zana.app` instead of an unpackaged Electron process.

---

_Nothing to migrate. Existing projects, plugins, and enrolled machines keep working. Pairing another computer still goes through this app's host daemon and the website relay._
