# What's new in 2.4.0

**A more complete Agentforce Studio, Squads that agents can launch, and plugin updates you control.** Zana 2.4 brings agent tabs, shared drafts, live test progress and simulation batches to the Studio. Modern Squads run as conversations, threads can open in their own windows, and independent plugins can update without waiting for a new Zana release.

## Agentforce Studio

- **Work on several agents.** Open agents in separate tabs. Each keeps its editor tabs, Assistant conversation and selected tools when you switch away and back.
- **One shared draft.** Studio and thread panels follow the same agent document. Unsaved edits survive closing and reopening the Studio, and proposed agent edits can be reviewed against the current draft. A thread's Agent panel brings together the file, Preview, Tests, Graph, Actions and Comments, with Open in Studio when you want to edit.
- **Tests in one place.** Browse local scenario suites and Salesforce Testing Center definitions with This agent / All agents, search and Has runs filters. Local suites remain available when the org cannot be reached. Expand a case to inspect its conversation, expectations, context and last result.
- **Follow a test as it runs.** See the current case, conversation turn, stage, completed count and elapsed time. Reopening Tests reconnects to an active run. Org eval shows elapsed time while Salesforce works, then displays the results it returns.
- **Run simulation batches.** Pick customer scenarios, repeat them, and follow each conversation in Simulate or Rehearse. Open transcripts, judge feedback and previous batches, stop a running batch, or ask the agent to improve failing conversations. AI judge verdicts are advisory; they do not qualify an agent for activation.
- **See test gaps on the graph.** Case results mark the topics and actions their expectations cover. Inspect failing cases and ask the agent to draft cases for uncovered parts. Hover highlights related nodes and connections without the rapid blinking or viewport jumps.
- **Preview context for you and your agent.** Agents can inspect available context fields, manage presets and start Preview with a saved preset. Preview's mode switches respond across the full visible label.
- **Smoother collaboration.** Agent requests keep your message short while passing the file, selection, problems and comments as context. Agent file writes refresh the open editor. Inline review comments are clickable, and comments can be edited or deleted.
- **A focused Studio.** Script, Preview, Tests, Graph and Org preview open as views of the active agent. Publishing, activation and deactivation go through the agent's lifecycle tools with confirmation in its thread; the Studio's Release tool and Publish button have been removed.
- **Faster org browsing.** Testing Center definitions load in batches and reuse cached summaries. Connected orgs show loading progress, schema search puts exact and prefix matches first, and the Problems count includes errors and warnings rather than informational messages.

## Squads

- **Ask an agent to start a Squad.** Agents can prepare a launch card for your review or start a run directly when the Squad and Project permit it. Either can require review before an agent-started launch proceeds. Results can report back to the owning conversation, with the Inbox as a fallback if it is gone.
- **Modern Squad conversations.** Modern orchestrators and workers run as ACP threads and appear together in Kanban, List, Workflow and the sidebar. Open a member's conversation from its row; CLI and Modern labels make the transport clear.
- **Squads and solo agents stay distinct.** Flow view labels solo agents separately, shows every orchestrator and sizes rows to keep cards from overlapping. Sidebar workers show their own session titles.
- **Attach plans from more places.** Pick, drop or @-mention a plan in your Project or an allowed location outside it. The proposal lists the attached sources for review. The picker opens in the Project, includes dot folders and preserves attachments after a failed launch.
- **Clearer plan correction.** Recoverable step labels and IDs are normalized automatically. Plans that need changes get a correction card naming the actual problem and the proposed correction. Cancelled correction runs explain why they cannot resume.
- **More reliable launches and reports.** Launchers use the Project whose chat or + button you clicked, including remote Projects. Terminal mouse and focus traffic no longer stalls Squad reports, and reports wait while you have an unsent draft.

## Plugins

- **Independent updates.** Git and npm plugins check for compatible updates, which you apply from Plugins or with `zcc plugin update <id>` and `zcc plugin update --all`. Updates keep the installed source, selector and subdirectory; exact versions, tags and commits stay pinned.
- **Bundled plugins keep their ownership.** Plugins shipped with Zana update with the application. Independent packages cannot replace a bundled identity, and application updates preserve your disabled or uninstalled choices, settings and stored data.
- **Recovery after failed updates.** Plugin activation records its progress and restores owned state after a failed or interrupted migration, so a partial update can recover on startup.
- **A clearer Plugins page.** Installed plugins use responsive cards and the catalogue uses the available width. Official catalogue changes become visible without a website redeploy.
- **Consistent side panels.** Plugin pages share the host's Agent tab, New Tab, resize, maximize and hide controls. Project plugin conversations keep the correct Project target, and side-panel tools stay with their page and window.

## Everyday work

- **Threads in their own windows.** Open a conversation and its side panel in a separate window. Split layouts survive new windows and relaunches.
- **Find and navigate faster.** Ctrl+F / Cmd+F opens thread search. Opening Settings focuses Search settings, and Find file focuses its input; Escape clears the query before closing. Opening a file reveals it in the Explorer tree.
- **Copy and reveal.** Fenced code blocks have a Copy button. File previews can reveal their file in Finder or Explorer, and editor buttons open the selected file in its Project.
- **Drafts stay put.** Composer messages, Inbox replies and Follow-up answers survive navigation. The Inbox reply bar stays visible while you read a long message, and read marks survive updates from another process.
- **Names and sessions survive restarts.** Manual thread names are preserved, Claude sessions follow thread renames, and sessions wait for their provider before resuming after a restart. Settings adds the idle timeout for releasing thread sessions.
- **Cleaner conversations and terminals.** Long prompts collapse according to their displayed height while assistant replies remain expanded. Returning to a terminal drops stale omitted-output markers, and Cmd+K clears the active terminal.
- **Steadier side panels and dictation.** Resizing a side panel no longer sticks or jumps when the pointer crosses an editor or preview, and voice input keeps working while remote machines are connected.

## Windows and remote access

- **Windows integration.** Open Projects in VS Code, Cursor or IntelliJ and launch an external terminal. Shortcuts use Ctrl, Alt and Shift labels. Salesforce CLI and Claude executable discovery, Claude skill links and backslash paths work correctly on Windows. The website links directly to Windows and both Mac installers.
- **More resilient Zana Connect.** Tunnel reconnects tolerate event-loop stalls and use staggered retries. Re-enrolling can reclaim your address, remote enrollment recovers more reliably, and a revoked connection shows a clear message with a sign-in action.
- **Browser panels return with their thread.** A side-panel browser revealed while its thread is in the background becomes visible when you open that thread.
