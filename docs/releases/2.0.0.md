# What's new in 2.0.0

A major Command Center release: Threads are the default way to work, plugins are a first-class platform, you can operate remote machines from the same workspace, and agent monitoring no longer borrows the coding-agent CLI.

## ✨ New

- **Threads are first-class.** New Chat starts a Thread by default. Threads appear on the Agents board, monitor, and tray alongside CLI agents, with a dedicated detail view, composer (model, reasoning, and mode), file previews, and voice input.
- **Home can launch an autonomous team** from the same composer, with a shared switcher between Thread and CLI Agent.
- **Plugins, not a second “extensions” product.** Installed packages (`package.json` `zcc`) add panels, project tabs, skills, MCP servers, settings, and CLI commands. Browse, git and subdirectory installs, and Create-your-own all live in Plugins.
- **Remote workspaces.** Enroll another machine, pick a host, add a remote project, and install the host daemon from the app. An in-app browser tab is available in the thread deck.
- **Explorer as a secondary panel** so you can keep files in view while you work.
- **Monitor semantic provider.** In Settings → Agents → Agent attention, choose OpenAI, Gemini, or no provider. This is used only for idle-agent triage and catch-up summaries, and it requires the matching key under Prompts. With no provider, board status stays deterministic and semantic results stay unavailable — there is no silent fallback to the Claude CLI.

## 💬 Improved

- **Clearer agent and thread chrome.** The thread detail view groups the timeline, banner, and composer in a centered column; busy threads cycle status phrases; board cards show runtime labels; nav badges stay live; and the composer shows sending states.
- **Idle-agent triage is contained.** Classification runs only through the selected HTTP provider, is rate-limited, and sends a redacted, size-capped transcript. Semantic facts are used for Claude sessions that actually support them — other harnesses are not guessed at.
- **A clearer Agents board in the docs.** The README screenshot is now an animated look at a multi-agent workspace.

## 🐛 Fixed

- **Monitor work cannot piggyback on the coding-agent CLI.** Idle triage and catch-up fail closed when no eligible HTTP provider is configured.
- **OpenCode “needs you” detection.** Confirmation and question prompts from OpenCode are recognized so those sessions surface as needing attention.
- **Auto-updates come from the public Zana releases.** The in-app updater reads [github.com/salesforce/zana](https://github.com/salesforce/zana) so signed builds pick up this feed.

## 🧪 Experimental

- **Catch-up summary.** Still off by default in Settings → Experimental. When enabled, it uses the Monitor semantic provider from Agents settings. Without a provider, summaries report unavailable.

---

_Idle-agent triage and catch-up summaries need OpenAI or Gemini configured under Prompts, then selected as the monitor provider. Without that, they stay off. Existing CLI agent sessions keep working — Threads do not require a migration._
