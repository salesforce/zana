# What's new in 1.0.8

A reliability-and-chat polish release: the chat surface reads and steers better, agents get their ZCC tools without prompting, adding a project is more forgiving, and a batch of Settings toggles that quietly did nothing now actually work.

## ✨ New

- **A richer, more readable chat.** Tool calls now render as clean, purpose-built cards instead of raw output, the composer remembers what you typed before so you can recall earlier prompts, and replies stream in as polished markdown. The whole transcript is easier to follow at a glance.
- **Type a project path by hand.** Adding a local project no longer depends on the folder picker cooperating — a new dialog lets you type or paste a path directly alongside Browse, so you can add a project on any machine or OS setup.

## 💬 Improved

- **Agents get their ZCC tools out of the box.** The built-in ZCC inbox tools are now pre-approved on every install and update, so agents stop asking for permission the first time they use them. Prefer the old behavior? Turn it off in Settings and your choice sticks.
- **OpenCode picks up exactly where you left off.** Restarting or reopening an OpenCode agent now resumes the specific conversation you were in, not just the most recent one — so the right context comes back every time.

## 🐛 Fixed

- **Settings toggles that do what they say.** Several switches had a control but no wiring behind them, so your choice was silently dropped on save. They now persist correctly — and the harness on/off switches stay in sync with the live setting instead of drifting.
- **Remote dev boxes honor your default path.** A hardcoded starting folder no longer overrides the global remote default when you add a remote project.
- **Extension badges stay fresh.** Navigation badges on extensions now refresh instead of showing stale, cached counts.
- **Agents launched from the app find their tools.** Improved how the app repairs its PATH at launch so command-line tools installed by dotfile-based installers are discovered reliably.
