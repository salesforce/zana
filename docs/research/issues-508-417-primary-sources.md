# Issues 508 and 417: primary-source research

Research date: 2026-10-28. Planning only; no runtime reproduction or implementation performed.

## Source-backed facts

- Node documents that a file URL's `pathname` is not a filesystem path: a Windows drive URL retains `/C:/`, UNC needs its authority, and encoded filenames require decoding. `fileURLToPath` handles these conversions, optionally using explicit Windows/POSIX semantics. Conversion still requires a separate containment check. [Node URL documentation](https://nodejs.org/api/url.html#urlfileurltopathurl-options).
- The URL Standard defines Windows drive letters and treats `file:` specially. Parsing can normalize dot segments, including encoded forms; preserve the distinction between URL parsing and filesystem authorization. [WHATWG URL Standard](https://url.spec.whatwg.org/#file-state).
- Node path operations default to the executing OS; `path.win32` and `path.posix` provide explicit semantics. A drive-relative `C:foo` is different from absolute `C:/foo`. Consequently, resolving a remote checkout must follow its authoritative root flavor, rather than the renderer or central server's OS. [Node path documentation](https://nodejs.org/api/path.html#windows-vs-posix).
- Electron recommends keeping Node integration disabled in renderers, retaining context isolation, and validating privileged IPC callers. Therefore importing `node:url` into a renderer helper or opening untrusted links through native shell APIs is inappropriate for this fix. [Electron security recommendations](https://www.electronjs.org/docs/latest/tutorial/security/).
- Filesystem `realpath` resolves symbolic links. Directory iteration supports asynchronous consumption and bounded buffering, but filesystem results can change between inspection and use. Revalidate at the actual read boundary and close resources on every path. [Node filesystem documentation](https://nodejs.org/api/fs.html#fspromisesrealpathpath-options).

## Recommendations inferred for Zana

These are engineering choices informed by the sources above and the repository, not requirements imposed by an external standard.

1. Keep renderer parsing pure and browser-compatible. Normalize recognized Windows-drive file URLs, decode once, reject malformed escapes, NUL/control input and unsupported authorities; retain existing rejection of network/UNC authorities unless deliberately adding an authorized UNC feature. Do not decode arbitrary raw paths a second time. Test encoded separators and traversal explicitly. If conversion moves into trusted Node code, use `fileURLToPath` with the authoritative host's path semantics rather than defaults.
2. Keep relative paths tied to the thread's recorded environment checkout; a CLI-agent panel uses its registered project scope. Do not silently substitute a different project checkout, local machine, or arbitrary working directory. Existing authority and confinement are in [preview-file.ts](../../apps/server/src/services/threads/preview-file.ts), [thread-host-file.ts](../../apps/server/src/services/threads/thread-host-file.ts), and [project-fs-via-host.ts](../../apps/server/src/http/project-fs-via-host.ts).
3. Try exact requested paths first. An explicitly supplied subdirectory path must not silently resolve to a different basename elsewhere. For bare filename fallback, prefer explicit message/file-read hints; any project search must run on the correct host and checkout. Search only after a genuine missing-file result, not permission denial, unavailable host or invalid scope.
4. If reusing `host.list_paths`, filter to exact basename matches: its existing ranking is fuzzy. Its results include a `truncated` flag; a single returned match with truncation does not prove uniqueness. Return an unresolved/ambiguous state rather than opening a plausible wrong file. The current project wrapper has no environment argument, so a thread resolver must not blindly call it for linked worktrees. [Host list implementation](../../apps/host-daemon/src/host-fs.ts), [project wrapper](../../apps/server/src/http/project-fs-via-host.ts), [RPC contract](../../packages/contracts/src/host-rpc.ts).
5. Bound discovery visits, result count, concurrency and elapsed time; avoid renderer-side whole-project indexing or synchronous main-process recursion. Preserve realpath confinement at read time. A path found by search is advisory, not authorization. The existing [path confinement package](../../packages/path-confine/src/index.ts) combines lexical and realpath checks; its null result intentionally combines missing and escaping paths, so do not label every null as definitely missing or weaken confinement to improve diagnostics.
6. Distinguish a missing file from resolution, scope, permission and host failures. Display the requested path and, where the authorized scope establishes it, the resolved attempted location. Do not assert that a missing report was generated or offer automatic script execution from an error view. The repository's [preview skill](../../apps/server/src/plugins/builtin-skills/zcc-preview/SKILL.md) already instructs agents to write or locate a file before previewing it.

## Suggested regression matrix

- Windows drive URL, lowercase drive, slash/backslash raw absolute paths, POSIX absolute path, relative subdirectory report, spaces and Unicode percent encoding, literal `%`/`#` filename handling, unsupported authority, malformed escape, encoded separator, NUL/control and encoded traversal.
- Existing root file wins; unique exact basename; duplicate basename; fuzzy-only results; truncated discovery; skipped/hidden directories; no candidate. Explicit `output/report.md` does not switch to `other/report.md`.
- Thread environment versus project root, linked worktree, remote host, CLI-agent owner, thread-storage source, stale hint, missing environment, unavailable host and read denial. Scope is authoritative even when the renderer supplies forged project/path fields.
- Symlink/junction escape, file replaced between discovery and read, read byte cap, cancellation/unmount, late results after thread switch, and repeated opens focusing the same logical tab.

Use focused behavior tests plus built-Electron end-to-end coverage for the renderer/server/host seam, following [AGENTS.md](../../AGENTS.md). This research does not establish a runtime root cause for #417: its report explicitly says the output may never have existed. Treat missing-file messaging and genuine resolution defects separately.
